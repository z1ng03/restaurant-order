# Arduino Uno + RFID-RC522: новая схема и запуск

Это учебная имитация оплаты: одна назначенная RFID-карта одобряется, вторая и неизвестные карты отклоняются. Банковские платежи не выполняются.

## Сначала провода

Отключите USB и любое внешнее питание. Переставляйте провода по маркировке контактов, а не по цветам проводов на фото.

| RC522 | Arduino Uno |
|---|---|
| 3.3V | 3.3V, НЕ 5V |
| GND | GND |
| SDA / SS | D10 через отдельный делитель 1 кОм / 2 кОм |
| SCK | D13 через отдельный делитель 1 кОм / 2 кОм |
| MOSI | D11 через отдельный делитель 1 кОм / 2 кОм |
| MISO | D12 |
| RST | D9 через отдельный делитель 1 кОм / 2 кОм |
| IRQ | не подключать |

На каждом из четырёх выходов Uno (D10, D13, D11, D9) соберите отдельный делитель: Arduino → 1 кОм → точка соединения → соответствующий вход RC522. Из той же точки → 2 кОм → GND. Так из 5V получается примерно 3.33V. Всего нужны 4×1 кОм и 4×2 кОм; каждый 2 кОм можно заменить двумя резисторами 1 кОм последовательно. Одиночный последовательный резистор не заменяет делитель. Провода делайте короткими, около 10 см. Делители не ставьте на питание 3.3V и на линию MISO. У RC522 питание и входы рассчитаны на 3.3V; наличие стабилизатора на модуле не означает допустимость 5V на сигнальных входах.

RGB-модуль с общим катодом (обычно контакт «−»): R → резистор 330 Ом → D5, G → отдельный 330 Ом → D6, B → отдельный 330 Ом → D7, общий → GND. Если модуль уже содержит резисторы, дополнительные уменьшат яркость, но допустимы. Проверяйте подписи R/G/B на плате, расположение контактов у модулей различается.

Для RGB с общим анодом: общий → 5V и COMMON_ANODE=true в прошивке. По представленным фотографиям тип общего контакта достоверно не установлен.

Пищалка не используется. Отключите её при снятом питании; D4 свободен.

## Прошивка

Основной скетч проекта: frontend/arduino/rc522_payment/rc522_payment.ino. Копия по старому пути frontend/arduino/rc522_payment.ino сохранена для совместимости.

В Arduino IDE установите библиотеку MFRC522 (miguelbalboa), выберите Arduino Uno и её COM-порт, загрузите скетч. После прошивки закройте монитор порта. Скетч и папка должны называться одинаково: rc522_payment.

## Назначение трёх меток

1. Откройте http://localhost:8000/rfid-setup.html в Chrome или Edge.
2. Нажмите «Подключить Arduino» и выберите плату в окне браузера.
3. Нажмите «Назначить карту „Успех“» и приложите первую карту. Уберите её.
4. Нажмите «Назначить карту „Отказ“» и приложите вторую карту. Уберите её.
5. Нажмите «Назначить брелок официанта», приложите третью метку и уберите её. В блоке привязки введите логин и пароль действующего официанта или администратора, нажмите «Привязать прочитанный брелок». Одна метка не может выполнять две роли. Назначения сохраняются в EEPROM после отключения питания.
6. Нажмите «Проверить карту» и проверьте каждую по очереди; перед каждым считыванием заново нажимайте кнопку.
7. Отдельно проверьте зелёный, красный и жёлтый кнопками страницы.
8. Нажмите «Отключить», чтобы освободить порт для корзины.

Белая карта и брелок должны быть совместимы с RC522 (13.56 MHz). UID определяется только считыванием, по внешнему виду его узнать нельзя.

## Оплата в ресторане

Откройте http://localhost:8000/index.html?monitor=1, добавьте блюдо, перейдите в корзину и выберите оплату картой. Подключите считыватель и приложите карту.

Синий: ожидание до 60 секунд. Зелёный и короткий сигнал: карта одобрена. Красный и два сигнала: отказ. При отказе заказ не создаётся и корзина сохраняется. Зелёный на устройстве подтверждает только учебную карту: успешное сохранение заказа подтверждает сайт после ответа сервера.

Если устройство сообщает RC522_NOT_FOUND — отключите USB и проверьте питание, GND, SDA, RST, SCK, MOSI, MISO. Если порт занят — закройте Arduino Serial Monitor и другие вкладки, использующие Arduino. Если цвета перепутаны — сверьте маркировку R/G/B. Если цвета инвертированы — проверьте общий анод/катод.

## Запуск проекта

Скрипт START_RESTAURANT.ps1 в корне запускает отдельную демо-базу на 127.0.0.1:5433, API на 4000 и сайт на 8000. STOP_RESTAURANT.ps1 останавливает только процессы из файла .local/runtime.json. Настройки подключения находятся в backend/.env; не публикуйте этот файл. Существующая системная база на 5432 не используется.

Официальная таблица подключения библиотеки: https://github.com/miguelbalboa/rfid#pin-layout


## Подготовленная сборка на этом ПК

После сборки схемы можно запустить UPLOAD_ARDUINO.bat в корне проекта: он загружает уже скомпилированную прошивку на COM3 и проверяет запись. Закройте Serial Monitor и отключите Arduino в браузере перед загрузкой. Для другого порта: powershell -File UPLOAD_ARDUINO.ps1 -Port COM4. Если меняете COMMON_ANODE или ACTIVE_BUZZER в исходнике, нужно заново скомпилировать и загрузить скетч через Arduino IDE: готовый HEX остаётся предыдущим.

## Подтверждение возраста брелком

В корзине с позициями 21+ нажмите «Подтвердить брелком официанта». Официант сначала проверяет документ гостя, затем прикладывает свой брелок. Жёлтый — ожидание; зелёный — сервер подтвердил действующего сотрудника и записал проверку для текущей сессии; красный — отказ. Карты оплаты не подтверждают возраст, брелок официанта не одобряет оплату. Ввод логина и пароля доступен отдельной кнопкой. При отключении USB, тайм-ауте или неизвестной метке возраст не подтверждается.

Для первой настройки обновите прошивку; существующие две метки формата EEPROM v2 сохраняются. Привязка третьей метки хранится и в Arduino, и в поле users.rfid_uid базы; повторная привязка сотрудника заменяет старый UID. При смене брелка повторите оба шага. Деактивированный сотрудник не сможет подтверждать возраст.

Это учебная система: UID RC522 копируется и не является криптографическим удостоверением сотрудника. Сервер запрещает этот способ при NODE_ENV=production; пароль продолжает работать.

Протокол v3: START_AGE → WAITING_FOR_CARD → AGE_CARD:<UID> либо AGE_DECLINED; AGE_TIMEOUT через 60 секунд. После AGE_CARD сайт проверяет UID на сервере и посылает TEST_GREEN / TEST_RED. CANCEL_AGE отменяет ожидание. ENROLL_WAITER назначает третью метку, STATUS возвращает WAITER_UID.
